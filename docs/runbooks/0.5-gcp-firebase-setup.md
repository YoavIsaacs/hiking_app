# Runbook 0.5 — GCP and Firebase setup (manager)

Source of truth: `docs/adr/0002-deployment.md` ("Manager console steps" 1-11, §1 identity, §2 roles, §9 GitHub).
You run everything below yourself. Agents never run cloud commands. All commands are **PowerShell** on Windows.
Estimated time: 45-60 minutes. Most commands are safe to re-run (`add-iam-policy-binding` is idempotent;
a `create` that says "already exists" is fine, move on).

> **Never**
> - Never create or download a service-account key (JSON). There are none in this design. If a screen offers one, decline.
> - Never put a secret, token or `.env` file in the repo. Everything here is an identifier, not a credential.
> - Never use `pull_request_target` in a workflow.
> - Never run `firebase init hosting:github` (it creates a key and a secret).
> - Never grant any role beyond the ones listed in step 6.

## 0. Prerequisites

1. Install the Google Cloud CLI and GitHub CLI (then open a **new** PowerShell window so `PATH` updates):
   ```powershell
   winget install -e --id Google.CloudSDK
   winget install -e --id GitHub.cli
   ```
2. Sign in:
   ```powershell
   gcloud auth login
   gh auth login
   gcloud components update
   ```
   `gcloud components update` matters: `--no-invoker-iam-check` (step 9) needs a recent gcloud.
   `gh` needs admin rights on `YoavIsaacs/hiking_app` (you are the owner).
3. You can open https://console.firebase.google.com with the same Google account.
4. You have a billing account. List it:
   ```powershell
   gcloud billing accounts list
   ```
   Note the `ACCOUNT_ID` (format `XXXXXX-XXXXXX-XXXXXX`).

| Placeholder | Value | How to get it |
| --- | --- | --- |

## Step 1. Project, billing, $5 budget alert

**What/why:** the container for everything; billing is required for Cloud Run and Artifact Registry.
Linking billing also moves Firebase to the **Blaze** (pay-as-you-go) plan automatically. Hosting keeps its no-cost
quota, so expected cost is about $0, but it is no longer hard-capped. The budget alert is the guard.

```powershell
gcloud projects create $PROJECT_ID --name="Hike Prep"
gcloud config set project $PROJECT_ID
gcloud billing projects link $PROJECT_ID --billing-account=$BILLING
$PROJECT_NUMBER = gcloud projects describe $PROJECT_ID --format="value(projectNumber)"
$PROJECT_NUMBER
```
Docs: https://docs.cloud.google.com/sdk/gcloud/reference/billing/projects/link

**Verify:**
```powershell
gcloud billing projects describe $PROJECT_ID --format="value(billingEnabled)"
```
Expected: `True`. Write down `$PROJECT_NUMBER` (also paste it into the session-variables block above).

**Budget alert** ($5/month, alerts at 50/90/100 % of current spend):
```powershell
gcloud billing budgets create --billing-account=$BILLING --display-name="hike-prep-5-per-month" --budget-amount=5 --calendar-period=month --filter-projects="projects/$PROJECT_NUMBER" --threshold-rule=percent=0.5 --threshold-rule=percent=0.9 --threshold-rule=percent=1.0
```
Docs: https://docs.cloud.google.com/sdk/gcloud/reference/billing/budgets/create (`percent` is 0.0-1.0).
The amount is in your billing account's currency (no currency suffix is passed). If gcloud asks to enable the
Billing Budgets API, answer `y`. If it fails with a permission error, use the console instead:
Console -> Billing -> Budgets & alerts -> Create budget -> scope: project `<PROJECT_ID>` -> amount: Specified amount,
`5` -> thresholds 50 %, 90 %, 100 % -> email notifications to you -> Finish.

**Verify:**
```powershell
gcloud billing budgets list --billing-account=$BILLING
```
Expected: one row, display name `hike-prep-5-per-month`.

**Undo:** budget: `gcloud billing budgets delete <BUDGET_NAME> --billing-account=$BILLING` (name from `list`).
Project (also deletes everything inside, 30-day grace): `gcloud projects delete $PROJECT_ID`. Project IDs cannot be reused.

## Step 3. Add Firebase to the project, set up Hosting

**What/why:** Firebase Hosting serves the web app and PR previews. It must live in the same GCP project.
**Console only** (gcloud cannot do this).

1. Open https://console.firebase.google.com -> **Add project** (or "Create a project").
2. Click **Select an existing Google Cloud project** and pick `<PROJECT_ID>`. Continue.
3. Accept the pricing change to **Blaze** (billing is already linked). Google Analytics is not needed: turn it off.
4. Wait for "Your project is ready".
5. Left menu -> Build -> **Hosting** -> **Get started**. Click through the wizard (Next, Next, Continue to console).
   You do **not** need to install anything or run the commands it shows.

> **Do NOT run `firebase init hosting:github`.** It creates a service-account key and stores it as a GitHub secret.
> Keyless deploys are set up by the workflows in this repo instead.

**Check: the default site ID must equal the project ID. If it does not, STOP and tell the tech lead.**
```powershell
$token = gcloud auth print-access-token
curl.exe -s -H "Authorization: Bearer $token" -H "x-goog-user-project: $PROJECT_ID" "https://firebasehosting.googleapis.com/v1beta1/projects/$PROJECT_ID/sites"
```
Docs: https://firebase.google.com/docs/reference/hosting/rest/v1beta1/projects.sites/list

**Expected:** JSON containing `"name": "projects/<PROJECT_ID>/sites/<PROJECT_ID>"` and
`"defaultUrl": "https://<PROJECT_ID>.web.app"`. Console equivalent: Hosting page shows the domain
`<PROJECT_ID>.web.app`. If the command returns an error such as "API not enabled", wait one minute and retry.
If the site ID is different (for example `<PROJECT_ID>-1a2b3`), stop here.

**Undo:** Firebase console -> Project settings -> (gear) -> "Delete project" removes the whole GCP project; to
only unlink Firebase there is no supported button, so ask the tech lead before experimenting.
Hosting site: Hosting page -> site menu -> Delete (the default site cannot be deleted, which is fine).

## Step 4. Artifact Registry Docker repository `hike`

**What/why:** stores the API images, tagged with the git SHA.

```powershell
gcloud artifacts repositories create hike --repository-format=docker --location=$REGION --description="Hike Prep API images" --project=$PROJECT_ID
```
Docs: https://docs.cloud.google.com/sdk/gcloud/reference/artifacts/repositories/create

**Verify:**
```powershell
gcloud artifacts repositories describe hike --location=$REGION --project=$PROJECT_ID --format="value(name,format)"
```
Expected: `projects/<PROJECT_ID>/locations/me-west1/repositories/hike   DOCKER`.

**Optional cleanup policy (keep the 10 newest versions, delete the rest; keeps storage under the free tier).**
Create a file `cleanup.json` in a scratch folder:
```powershell
@'
[
  {"name": "keep-10-newest", "action": {"type": "Keep"}, "mostRecentVersions": {"keepCount": 10}},
  {"name": "delete-others", "action": {"type": "Delete"}, "condition": {"tagState": "any"}}
]
'@ | Set-Content -Encoding ascii cleanup.json
gcloud artifacts repositories set-cleanup-policies hike --location=$REGION --policy=cleanup.json --project=$PROJECT_ID
gcloud artifacts repositories list-cleanup-policies hike --location=$REGION --project=$PROJECT_ID
```
Docs: https://docs.cloud.google.com/artifact-registry/docs/repositories/cleanup-policy and
https://docs.cloud.google.com/sdk/gcloud/reference/artifacts/repositories/set-cleanup-policies
Expected: both policies listed. (The repo is empty now; a "Keep" rule wins over "Delete", so this only removes
versions older than the newest 10.) Skip this if unsure; it is optional in the ADR.

**Undo:** `gcloud artifacts repositories delete hike --location=$REGION --project=$PROJECT_ID`
(deletes all images). Policies: `gcloud artifacts repositories delete-cleanup-policies hike --location=$REGION --policy-names=keep-10-newest,delete-others`.

**What/why:** separate identities: `api-deploy` (CI deploys the API), `api-runtime` (what the running API uses),

```powershell
gcloud iam service-accounts create web-deploy  --display-name="Web deploy (GitHub Actions)"  --project=$PROJECT_ID
```

**Verify:**
```powershell

```
Expected: lines for `api-deploy@`, `api-runtime@`, `web-deploy@` `<PROJECT_ID>.iam.gserviceaccount.com`
(plus the default compute SA and possibly Firebase ones; ignore those, never use them).

**Undo:** `gcloud iam service-accounts delete <email> --project=$PROJECT_ID` (also removes its bindings).

## Step 6. Grant the roles (exactly the ADR §2 table, each on its stated resource)

**What/why:** least privilege. Each role is bound at the narrowest resource that supports it.
`--condition=None` is only needed on project-level bindings (stops gcloud prompting).

| SA | Role | Bound on |
| --- | --- | --- |
| `api-deploy` | `roles/run.admin` | project |
| `api-deploy` | `roles/artifactregistry.writer` | repository `hike` only |
| `api-deploy` | `roles/iam.serviceAccountUser` | service account `api-runtime` only |
| `api-runtime` | `roles/secretmanager.secretAccessor` | project |
| `web-deploy` | `roles/firebasehosting.admin` | project |
| `web-deploy` | `roles/serviceusage.apiKeysViewer` | project |

```powershell
# api-deploy
gcloud projects add-iam-policy-binding $PROJECT_ID --member="serviceAccount:$API_DEPLOY" --role="roles/run.admin" --condition=None
gcloud artifacts repositories add-iam-policy-binding hike --location=$REGION --project=$PROJECT_ID --member="serviceAccount:$API_DEPLOY" --role="roles/artifactregistry.writer"
gcloud iam service-accounts add-iam-policy-binding $API_RUNTIME --project=$PROJECT_ID --member="serviceAccount:$API_DEPLOY" --role="roles/iam.serviceAccountUser"

# api-runtime (no secrets exist yet; ready for later)
gcloud projects add-iam-policy-binding $PROJECT_ID --member="serviceAccount:$API_RUNTIME" --role="roles/secretmanager.secretAccessor" --condition=None

# web-deploy
gcloud projects add-iam-policy-binding $PROJECT_ID --member="serviceAccount:$WEB_DEPLOY" --role="roles/firebasehosting.admin" --condition=None
gcloud projects add-iam-policy-binding $PROJECT_ID --member="serviceAccount:$WEB_DEPLOY" --role="roles/serviceusage.apiKeysViewer" --condition=None
```
Docs: https://docs.cloud.google.com/sdk/gcloud/reference/projects/add-iam-policy-binding ,
https://docs.cloud.google.com/sdk/gcloud/reference/artifacts/repositories/add-iam-policy-binding ,
https://docs.cloud.google.com/sdk/gcloud/reference/iam/service-accounts/add-iam-policy-binding

**Verify (project-level roles per SA):**
```powershell
foreach ($sa in @($API_DEPLOY, $API_RUNTIME, $WEB_DEPLOY)) {
  "== $sa"
  gcloud projects get-iam-policy $PROJECT_ID --flatten="bindings[].members" --filter="bindings.members=serviceAccount:$sa" --format="value(bindings.role)"
}
```
Expected:
- `api-deploy`: `roles/run.admin` only
- `api-runtime`: `roles/secretmanager.secretAccessor` only
- `web-deploy`: `roles/firebasehosting.admin` and `roles/serviceusage.apiKeysViewer`

**Verify (resource-level):**
```powershell
gcloud artifacts repositories get-iam-policy hike --location=$REGION --project=$PROJECT_ID
gcloud iam service-accounts get-iam-policy $API_RUNTIME --project=$PROJECT_ID
```
Expected: the first lists `roles/artifactregistry.writer` for `api-deploy`; the second lists
`roles/iam.serviceAccountUser` for `api-deploy`.

**Undo:** swap `add-` for `remove-` in the same command (`gcloud projects remove-iam-policy-binding ...`, same flags).

## Step 7. Workload Identity pool `github` and provider `hiking-app`

**What/why:** lets GitHub Actions prove who it is (OIDC) and get short-lived Google credentials, with no key.
The provider **condition** only accepts tokens from this repo (numeric IDs, so a re-registered name cannot
impersonate it) running on `main` or on PRs targeting `main`. Which service account a run may impersonate is
decided separately in step 8.

```powershell
gcloud iam workload-identity-pools create github --project=$PROJECT_ID --location=global --display-name="GitHub Actions"

$MAPPING = "google.subject=assertion.sub,attribute.repository_id=assertion.repository_id,attribute.repository_owner_id=assertion.repository_owner_id,attribute.ref=assertion.ref,attribute.event_name=assertion.event_name"
$CONDITION = "assertion.repository_id == '$REPO_ID' && assertion.repository_owner_id == '$OWNER_ID' && (assertion.ref == 'refs/heads/main' || (assertion.event_name == 'pull_request' && assertion.base_ref == 'main'))"

gcloud iam workload-identity-pools providers create-oidc hiking-app --project=$PROJECT_ID --location=global --workload-identity-pool=github --display-name="hiking-app" --issuer-uri="https://token.actions.githubusercontent.com" --attribute-mapping="$MAPPING" --attribute-condition="$CONDITION"
```
Docs: https://docs.cloud.google.com/sdk/gcloud/reference/iam/workload-identity-pools/providers/create-oidc ;
background: https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines

**Verify:**
```powershell
gcloud iam workload-identity-pools providers describe hiking-app --project=$PROJECT_ID --location=global --workload-identity-pool=github --format="yaml(name,state,attributeCondition,attributeMapping,oidc.issuerUri)"
```
Expected: `state: ACTIVE`; `name: projects/<PROJECT_NUMBER>/locations/global/workloadIdentityPools/github/providers/hiking-app`;
`attributeCondition` contains your two numeric IDs (not `<REPO_ID>` text) and `refs/heads/main`;
`issuerUri: https://token.actions.githubusercontent.com`.

**Undo:** providers are soft-deleted (30 days) and the name stays reserved while deleted. To fix a mistake prefer
`gcloud iam workload-identity-pools providers update-oidc hiking-app ... --attribute-condition=...` (same flags as create).
To remove: `gcloud iam workload-identity-pools providers delete hiking-app --project=$PROJECT_ID --location=global --workload-identity-pool=github`,
then the pool: `gcloud iam workload-identity-pools delete github --project=$PROJECT_ID --location=global`.
If you delete and need the same name back before 30 days: `... providers undelete hiking-app ...`.

## Step 8. Let the right GitHub subjects impersonate the right service accounts

**What/why:** `roles/iam.workloadIdentityUser` on each SA, granted to one exact GitHub "subject":
- `api-deploy`: only jobs that declare `environment: production` (and that environment admits only `main`).
- `web-deploy`: the same, **plus** `pull_request` runs (for preview channels).
A PR job can therefore never act as `api-deploy`.

```powershell
$POOL = "principal://iam.googleapis.com/projects/$PROJECT_NUMBER/locations/global/workloadIdentityPools/github/subject"
$SUB_ENV = "repo:${REPO}:environment:production"
$SUB_PR  = "repo:${REPO}:pull_request"

gcloud iam service-accounts add-iam-policy-binding $API_DEPLOY --project=$PROJECT_ID --role="roles/iam.workloadIdentityUser" --member="$POOL/$SUB_ENV"
gcloud iam service-accounts add-iam-policy-binding $WEB_DEPLOY --project=$PROJECT_ID --role="roles/iam.workloadIdentityUser" --member="$POOL/$SUB_ENV"
gcloud iam service-accounts add-iam-policy-binding $WEB_DEPLOY --project=$PROJECT_ID --role="roles/iam.workloadIdentityUser" --member="$POOL/$SUB_PR"
```
Docs: https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines

**Verify:**
```powershell
gcloud iam service-accounts get-iam-policy $API_DEPLOY --project=$PROJECT_ID
gcloud iam service-accounts get-iam-policy $WEB_DEPLOY --project=$PROJECT_ID
```
Expected: `api-deploy` has exactly one `roles/iam.workloadIdentityUser` member
(`principal://.../subject/repo:YoavIsaacs/hiking_app:environment:production`); `web-deploy` has two
(`...:environment:production` and `...:pull_request`). Note the repo name is in the subject, so renaming the GitHub repo
breaks deploys (it fails closed; redo this step).

**Undo:** `gcloud iam service-accounts remove-iam-policy-binding <SA> --role="roles/iam.workloadIdentityUser" --member="<same member>"`.

## Step 10. GitHub variables and the `production` environment

**What/why (ADR §9):** no secrets at all. Everything is an identifier; protection comes from the WIF condition and
subject bindings. Environment `production` admits only `main`, which is what makes the `environment:production`
subject trustworthy. No required reviewers and no wait timer (they would block the automatic deploy).

**10a. Repository variables** (used by deploys and previews):
```powershell
gh variable set GCP_PROJECT_ID   --repo $REPO --body $PROJECT_ID
gh variable set GCP_REGION       --repo $REPO --body $REGION
gh variable set GCP_WIF_PROVIDER --repo $REPO --body "projects/$PROJECT_NUMBER/locations/global/workloadIdentityPools/github/providers/hiking-app"
gh variable set WEB_DEPLOY_SA    --repo $REPO --body $WEB_DEPLOY
```

**10b. Environment `production`, restricted to `main`:**
```powershell
'{"deployment_branch_policy":{"protected_branches":false,"custom_branch_policies":true}}' | gh api -X PUT "repos/$REPO/environments/production" --input -
gh api -X POST "repos/$REPO/environments/production/deployment-branch-policies" -f name=main -f type=branch
```
Docs: https://docs.github.com/en/rest/deployments/environments and
https://docs.github.com/en/rest/deployments/branch-policies
Console equivalent: repo -> Settings -> Environments -> New environment `production` -> Deployment branches and tags
-> "Selected branches and tags" -> Add deployment branch or tag rule -> `main`. Leave "Required reviewers" and
"Wait timer" off.

**10c. Environment variables:**
```powershell
gh variable set API_DEPLOY_SA  --env production --repo $REPO --body $API_DEPLOY
gh variable set API_RUNTIME_SA --env production --repo $REPO --body $API_RUNTIME
```

**10d. Fork-PR token setting (console only):** repo -> Settings -> Actions -> General -> **Fork pull request workflows
from outside collaborators** (public repos). Confirm **"Send write tokens to workflows from pull requests" is
unchecked**, and also leave "Send secrets and variables to workflows from pull requests" unchecked. Click Save if
you changed anything. This is what stops fork PRs from getting an OIDC token. Doc:
https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository

**Verify:**
```powershell
gh variable list --repo $REPO
gh variable list --env production --repo $REPO
gh api "repos/$REPO/environments/production" --jq "{name, branch_policy: .deployment_branch_policy, rules: [.protection_rules[].type]}"
gh api "repos/$REPO/environments/production/deployment-branch-policies" --jq ".branch_policies[] | {name, type}"
```
Expected:
- repo variables: `GCP_PROJECT_ID`, `GCP_REGION`, `GCP_WIF_PROVIDER`, `WEB_DEPLOY_SA` with your values
- env variables: `API_DEPLOY_SA`, `API_RUNTIME_SA`
- environment: `custom_branch_policies: true`, `protected_branches: false`, `rules` containing `branch_policy` and
  no `required_reviewers` / `wait_timer`
- branch policies: exactly `{"name":"main","type":"branch"}`
- `gh secret list --repo $REPO` returns nothing (there are no secrets).

**Undo:** `gh variable delete <NAME> --repo $REPO` (add `--env production` for environment variables);
`gh api -X DELETE "repos/$REPO/environments/production"`.
