# Step 0.6 — Pipeline rules

Branch: `step/0.6-pipeline-rules` · Phase: 0 · Status: briefing

## Goal
The repo enforces the process: nothing reaches `main` except through a PR with green required checks, CI runs
only what a change touches and stays fast, a nightly run catches dependency drift, and releases get a changelog
from release-please.

## Checkpoint
"PR pipeline < 5 min; merge to `main` live in < 10 min; 0 ways to push to `main` without green checks" —
how it will be measured:
- PR pipeline: wall time from first check start to last check end on this step's PR (`gh run list`/`gh run view` timings, all PR workflows).
- Merge to live: merge commit time → `/health` on the live API returns that `git_sha` and the web deploy run ends; from `gh run view` of Deploy API / Deploy Web.
- 0 ways: `gh api repos/{owner}/{repo}/rules/branches/main` shows `pull_request`, `required_linear_history`,
  `non_fast_forward`, `deletion`, `required_status_checks` (all listed checks); ruleset has no bypass actors;
  direct push rejected; failing-test PR `BLOCKED`.
