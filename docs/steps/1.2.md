# Step 1.2 — GPX parser — `POST /v1/routes/parse`

Branch: `step/1.2-gpx-parser` · Phase: 1 · Status: PR

## Goal
`POST /v1/routes/parse` turns a GPX upload into a typed `RouteSummary` (distance within 2 % and gain within 10 % of the
reference on every valid 1.1 fixture), rejects bad input with a typed `ErrorResponse`, never returns 500, and parses the
largest fixture in < 2 s, with a CI benchmark guarding regressions.

## Agents
`architect` (ADR: parser module boundary, `RouteSummary`/`ErrorResponse` contract, algorithm choices and their
parameters, new dependencies) → backend contract stub → `qa` red tests → `backend-expert` build + `pnpm gen:api` →
`devops` (benchmark job) → `qa` verify → `reviewer`. Skipped: ux / graphic-designer (no screen; 1.10 consumes this),
frontend (only the regenerated client, done by `just gen-api`), mobile (Phase 5+).

From `docs/roadmap/overview.md` 1.2:
- Parse with gpxpy; accept `<trk>` and `<rte>`; merge segments
- Distance via geodesic distance between points
- Elevation gain and loss with smoothing (moving average plus a small noise threshold), since raw GPS elevation overstates gain
- Min/max elevation, high-point coordinates, start and end points
- Down-sample the track to ≤ 500 points with Ramer–Douglas–Peucker for the frontend
- Reject files > 10 MB; return 422 with a clear message for invalid GPX
