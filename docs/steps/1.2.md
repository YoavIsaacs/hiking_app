# Step 1.2 — GPX parser — `POST /v1/routes/parse`

Branch: `step/1.2-gpx-parser` · Phase: 1 · Status: tests (contract stub)

## Goal
`POST /v1/routes/parse` turns a GPX upload into a typed `RouteSummary` (distance within 2 % and gain within 10 % of the
reference on every valid 1.1 fixture), rejects bad input with a typed `ErrorResponse`, never returns 500, and parses the
largest fixture in < 2 s, with a CI benchmark guarding regressions.

## Agents
`architect` (ADR: parser module boundary, `RouteSummary`/`ErrorResponse` contract, algorithm choices and their
parameters, new dependencies) → backend contract stub → `qa` red tests → `backend-expert` build + `pnpm gen:api` →
`devops` (benchmark job) → `qa` verify → `reviewer`. Skipped: ux / graphic-designer (no screen; 1.10 consumes this),
frontend (only the regenerated client, done by `just gen-api`), mobile (Phase 5+).

## Checklist
Copied verbatim from `docs/roadmap/phase-1.md` § 1.2. Owners: Models/Logic/Endpoint — backend (after architect ADR);
Tests — qa (acceptance/property/endpoint) + backend (unit tests for internals); CI — devops (benchmark), backend (`gen:api`).


**Models** (`app/models/route.py`)

- [ ] `TrackPoint`: `lat`, `lon`, `elev_m: float | None`, `dist_m` (cumulative)
- [ ] `LatLonElev`: `lat`, `lon`, `elev_m`
- [ ] `RouteSummary`: `name`, `distance_m`, `gain_m`, `loss_m`, `min_elev_m`, `max_elev_m`, `high_point: LatLonElev`, `start: LatLonElev`, `end: LatLonElev`, `is_loop: bool`, `points: list[TrackPoint]` (≤ 500), `has_elevation`, `elevation_source` (`file` / `lookup` / `none`), `source_format` (`trk` / `rte`), `point_count_original`
- [ ] `ErrorResponse`: `code`, `message`, `detail` (shared by all endpoints)

**Logic** (`app/routes/`)

- [ ] `parse_gpx(bytes) → RawTrack` with gpxpy; prefer `<trk>`, fall back to `<rte>`
- [ ] Merge all segments in order; drop consecutive duplicate points
- [ ] Reject a file with < 2 points (422 `too_few_points`)
- [ ] `geodesic_distance()` between consecutive points (geographiclib or haversine; pick one and document it)
- [ ] `smooth_elevation()` — moving-average window (configurable, e.g. 5 points)
- [ ] `gain_loss()` — accumulate only changes beyond a noise threshold (configurable, e.g. 3 m)
- [ ] `is_loop` — start and end within a threshold (e.g. 200 m)
- [ ] `simplify()` — Ramer–Douglas–Peucker until ≤ 500 points; always keep start, end and high point
- [ ] Name from GPX metadata, else from the filename

**Endpoint** (`app/routers/routes.py`)

- [ ] `POST /v1/routes/parse`, multipart field `file`
- [ ] Size check before parsing: > 10 MB → 413 `file_too_large`
- [ ] Invalid XML or not GPX → 422 `invalid_gpx`
- [ ] All parsing exceptions mapped to `ErrorResponse`; nothing escapes as 500
- [ ] Response model declared so the OpenAPI schema is fully typed

**Tests** (`tests/routes/`)

- [ ] Parametrised: distance within 2% of reference for each valid fixture
- [ ] Parametrised: gain within 10% for each fixture with elevation
- [ ] Malformed file → 422; KML file → 422; 11 MB file → 413; 1-point file → 422
- [ ] `<rte>` fixture parses with `source_format = rte`
- [ ] Multi-segment fixture distance doesn't include the jump between segments (if that's your chosen behaviour — decide and test it)
- [ ] `simplify()` output ≤ 500 points and keeps start, end, high point
- [ ] Loop fixture `is_loop = true`; out-and-back `is_loop = true`; one-way route `false`
- [ ] Hypothesis: random tracks → distance ≥ 0, gain ≥ 0, loss ≥ 0
- [ ] Hypothesis: reversed track → same distance, gain and loss swapped
- [ ] Endpoint tests through `TestClient` for 200, 413, 422
- [ ] pytest-benchmark on the largest fixture

**CI**

- [ ] `api-test` runs the new tests
- [ ] Benchmark job stores the baseline (github-action-benchmark) and fails on > 20% regression
- [ ] Regenerate the client; `api-contract` green


From `docs/roadmap/overview.md` 1.2:
- Parse with gpxpy; accept `<trk>` and `<rte>`; merge segments
- Distance via geodesic distance between points
- Elevation gain and loss with smoothing (moving average plus a small noise threshold), since raw GPS elevation overstates gain
- Min/max elevation, high-point coordinates, start and end points
- Down-sample the track to ≤ 500 points with Ramer–Douglas–Peucker for the frontend
- Reject files > 10 MB; return 422 with a clear message for invalid GPX

## Inputs from 1.1 (see `docs/steps/1.1.md` "Follow-ups for 1.2")
- Raw gain vs AllTrails: Modiin 245/198, Ben Shemen 375/200, Tel Hadid 236/103 m. Smoothing must be tuned against these;
  if 10 % proves unreachable with a principled method, escalate to the manager — never fit per file or loosen the gate.
- The > 10k fixture is a 14× linear densification of Ben Shemen: a point-count window barely smooths it, so smoothing and
  the noise threshold should be distance-based (or otherwise density-independent).
- Multi-segment fixture: 34.1 m jump between segments; either choice stays within 2 % of 6400 m. Decide and test it.
- Reference distances are rounded to 0.1 km (±50 m).
- Invalid fixtures expect `invalid_gpx`.

## Decisions and deviations
- 2026-10-19 — Path is `/v1/routes/parse` (phase-1 checklist) though `overview.md` says `/routes/parse` — mirror inconsistency; **manager confirmed `/v1` 2026-10-19** (he corrects the master doc).
- 2026-10-19 — ADR 0004 (architect) accepted by tech lead, pending the manager's dependency approval. Key calls:
  haversine (no geographiclib); segment jumps **counted**; elevation resampled by distance (5 m) → moving average in
  metres → hysteresis threshold, defaults tuned on a fixed grid by best worst-case margin (no per-file parameters; if no grid
  point passes, escalate); ranked iterative RDP to exactly min(n, 500); no defusedxml — a stdlib prolog guard rejects
  DTD/entities and non-`<gpx>` roots; 3-layer 10 MiB upload cap; `summarise_gpx` runs in a threadpool.
- 2026-10-19 — Deviation from the checklist heading: `ErrorResponse` lives in `app/models/errors.py` (shared by all endpoints), not `app/models/route.py`. Tech lead (ADR 0004).
- 2026-10-19 — The existing 500 body changes to `ErrorResponse` (`internal_error`); QA updates the body assertion in `api/tests/test_errors.py`.
- 2026-10-19 — Benchmark: A/B (base vs head in the same job), `min` of 10 rounds, fails on > 20 % or ≥ 2 s; history in `actions/cache` (no manager action). Job name `benchmark`.
- 2026-10-19 — Out of scope, noted: CORS `POST` for the upload → 1.10; hostile-file CPU cost (point cap / rate limit) → later follow-up.
