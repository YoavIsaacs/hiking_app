# Step 1.1 — GPX test corpus

Branch: `step/1.1-gpx-test-corpus` · Phase: 1 · Status: briefing (waiting on manager files + reference values)

## Goal
`api/tests/fixtures/gpx/` holds 10 committed GPX fixtures from ≥ 4 sources covering the 7 edge cases, each with an
`expected.json` entry carrying the source app's reference values, and a test fails if any file and entry don't match up.

## Decisions and deviations
- 2026-10-19 — Fixture filenames are ASCII slugs (`<source>-<slug>.gpx`); the original filename goes in `expected.json` `original_name`. Tech lead.
- 2026-10-19 — Derived edge-case files (no-ele, `<rte>`, multi-segment, malformed, KML) are made from a real fixture by a small, deterministic transform; `expected.json` records `derived_from` and inherits the parent's reference values (no-ele: gain `null`, `has_elevation: false`). Tech lead.
- 2026-10-19 — The 3 supplied AllTrails files are planned routes (no timestamps), all loops, start == end at public trailheads → no home-location trim needed. Tech lead.
- Pending — if no real > 10,000-point recording arrives, QA densifies a real track by interpolation (marked `derived_from`). Needs no manager decision unless sources drop below 4.
