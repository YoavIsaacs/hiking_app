# Step 1.3a — Hardening after 1.3 (not a roadmap step)

Branch: `step/1.3a-hardening` · Phase: 1 · Status: review

## Goal
The API image is built and checked on every PR that can change it, `/health` reports the real release version, and
repeated hostile uploads no longer push the API's memory towards Cloud Run's 512 MiB limit.

## Checklist
Not from `docs/roadmap/`. This step is a manager-approved insert between 1.3 and 1.4 (2026-11-01). The items come from
1.3's follow-ups, the 0.6 carry-forward and ADR 0004 item 55.

Agents: `devops` (version wiring, image job); `backend-expert` (investigate, fix); `qa` (probe, measure, verify);
`architect` (ADR 0004 amendment for the chosen RSS option); `reviewer`. UX, graphic designer, frontend and mobile are
skipped: nothing here touches a screen.

- [ ] **Release version wiring (manager option (a), 2026-11-01).** release-please also bumps `api/pyproject.toml`
      `version` (and keeps `api/uv.lock` in sync), so `/health` `version` equals the released version. A CI check
      fails if `api/pyproject.toml` and `.release-please-manifest.json` disagree. — devops
- [ ] **`api-image` PR job (manager-approved new required check, 2026-11-01).** Runs on PRs and `main` pushes that
      touch `api/**` (Dockerfile, `.python-version`, `pyproject.toml`, `uv.lock`, app code). Steps:
      `docker build` (the drift guard runs inside it), then run the container, check `/health` 200 with the build
      args, check uid 10001, and run QA's RSS probe (below) against it. It skips cleanly, without failing, when no
      api path changed, the same way the other path-filtered jobs do. — devops (job), qa (probe script)
- [ ] **RSS ratchet (ADR 0004 item 55).** Find the cause using the ADR 0004 follow-up "Investigate the RSS ratchet"
      (tracemalloc vs RSS, `gc.collect()`/`gc.garbage`, `sys._debugmallocstats()`, a `malloc_trim(0)` probe). Pick
      an option from that list, record it as an ADR 0004 amendment, and implement it. — backend (investigate, fix), qa
      (measure), architect (amendment), devops (only if it touches the Dockerfile)
- [ ] **RSS probe as an automated check.** A script owned by QA (`api/tests/routes/` harness style). It runs inside
      the built image and posts N sequential hostile H2 U=256 uploads over HTTP to a fresh container. It fails if
      RSS passes the bar. It runs in `api-image`. — qa

## Checkpoint
Set by the tech lead (no roadmap checkpoint):
- **(1)** In `hike-api` built from the branch, at `--memory=512m`, 60 sequential H2 U=256 uploads keep RSS at
  **≤ 200 MiB** after the first 10. Today it is 383 → 398 MiB.
- **(2)** The C = 8 concurrent hostile-upload smoke peaks at **< 400 MiB**, with no OOM and no 500.
- **(3)** H11(d) stays **< 3.5 s**.
- **(4)** After merging the next release PR, live `/health` `version` equals the release tag without the `v` (tag `v0.3.0` → `0.3.0`).

Measured by QA's probe, locally and in `api-image`; (4) by curl after the release.

## Out of scope
- Lowering Cloud Run `--concurrency` (manager decision, item 53). Only proposed if no in-process option meets the
  checkpoint.
- New allocators (jemalloc or mimalloc) need their own ADR and manager approval. Only proposed if nothing else works.
- Building the image on the web-only path.

## Decisions and deviations
- 2026-11-01 — Manager: wire release version → API (option a); approve the new required check `api-image`.
- 2026-11-01 — Tech lead: insert as step 1.3a before 1.4. The RSS ratchet predates 1.3 (since 1.2); the
  checkpoint bars above are a tech-lead call within the approved scope.
- 2026-11-01 — Review round 1 (reviewer: changes needed). Blocking: the probe's single end-to-end H11(d) < 3.5 s
  bar would flake in a required check (reviewer host 3.05–4.36 s, one run inflated by a 1.25 s failed elevation
  lookup). **Tech lead decision:** `api-image` gates memory and status bars only; H11(d) is measured (median of 3,
  lookup time reported separately) and printed as a `::warning::` over 3.5 s, not a failure. Checkpoint (3) is
  measured locally by QA (n = 8 × 3 rounds, item 54's method: max 2.90 s) and tracked in ADR 0004 §3.13. Should-fix:
  probe asserts 422/200 statuses (qa); ADR item 56 stale testing/follow-up text, no-swap pre-fix OOM at ~45 uploads,
  S re-check recorded (architect); nits batched (qa, backend, devops). The release-please jsonpath comment nit can't go
  in JSON; devops documents it in the ci.yml version-sync comment instead.
